## Tier-1 — Automatic (Low-Risk)

**Workflow:** `08-self-healing-tier1.json` — every 10 min  
**Gate:** `scripts/gate_check.sh` must exit 0 before any action

| Trigger | Threshold | Action | Max rate |
|---|---|---|---|
| Disk usage | >= 85% | Delete `*.gz` older 7d + journalctl vacuum 200M | 1x/hr |
| Runner fail streak | >= 3 failed units | `systemctl restart actions.runner.*` | 2x/hr |
| Webhook blocked | >= 10/min | Suspend flow 5 min + alert | — |

All actions write to `event_log` with `source=08-self-healing-tier1`.

---

## Tier-2 — Human-Approved (Medium/High Risk)

**Workflow:** `09-self-healing-tier2.json` — every 15 min  
**Pattern:** detect critical event → Telegram alert → wait for `/approve_*`

| Trigger | Alert | Approval cmd | Timeout |
|---|---|---|---|
| `disk_crit` | Archive large log dirs | `/approve_disk_archive` | 15 min |
| `runner_down_all` | Spawn runner on AVM-03 | `/approve_runner_spawn` | 15 min |
| `n8n_all_fail` | Restore from backup (dry-run shown) | `/approve_n8n_restore` | 15 min |

**No approval within 15 min → NO action. Alert persists.**

## Meta-Evaluator — Weekly Self-Tuning

**Workflow:** `10-meta-evaluator-weekly.json` → `scripts/meta_evaluator.py`  
**Cadence:** Every Sunday 23:00 UTC

### Flags

| Condition | Action |
|---|---|
| `accept_rate < 50%` (>=5 events) | Flag `low_accept_rate` → Telegram + `META_EVAL_THRESHOLD` event |
| `false_positive > 20%` (>=5 events) | Flag `high_false_positive` → Telegram + `META_EVAL_THRESHOLD` event |

### Applying a threshold change

1. Read Telegram message.
2. Check Neon:
   ```sql
   SELECT context, outcome FROM event_log
   WHERE event_type = 'meta_eval_threshold_change'
   ORDER BY ts DESC LIMIT 10;
   ```
3. Update threshold in `config/loops/thresholds.yaml`.
4. Workflows read this config on next run.
